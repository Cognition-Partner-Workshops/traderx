## Evidence-head assessment and residual changes

1. **Requirement 1: gap despite correct processor history writes.** Evidence `TradeService.java:39-97` already records New, Processing and Settled atomically; its `TradeStatusHistory.java:41-43` maps UTC. However, evidence `database/run.sh:24` executes destructive schema initialization on every start, and `database/initialSchema.sql:27-29` has no database-level update/delete protection. Bootstrap trades also lack their initial history rows. The extension preserves existing databases, adds append-only enforcement and initial sample records, and makes the migration idempotent.
2. **Requirement 2: met**, with no residual change required.
3. **Requirement 3: gap.** Evidence account REST JSON still exposes numeric IDs (`account-service/src/main/java/finos/traderx/accountservice/model/Account.java:29-30`). Its HTTP masking module deliberately leaves internal order transport numeric (`trade-service/src/main/java/finos/traderx/tradeservice/AccountMaskingModule.java:11-24`), while `trade-feed/index.js:47-66` broadcasts those payloads unchanged to clients, including wildcard subscribers. Processor topics also embed numeric keys (`TradeService.java:80-81`). Legacy sample trade IDs contain complete account numbers, reaching position-service trade responses; general exception handlers echo unsanitized exception messages.

The extension adds persisted UUID public references, shared serialization/path resolution, safe legacy trade-ID serialization, sanitized broker publication/subscription boundaries, and generic unexpected errors. Internal numeric database keys remain unchanged and numeric input remains supported. Orders include the public reference before the broker replaces numeric transport keys; processor deserialization resolves references back to numeric keys. HTTP trade/position account fields remain masked. Angular now displays the supplied masked accountNumber while routing with opaque keys; its type changes follow that contract.

Shared-module Gradle settings/dependencies and Docker build contexts were changed only because all four Java services need that module. Trade-service gains database connectivity for reference resolution. Public references are routing identifiers, not authorization credentials.

Other surfaces/path checks:

- Production `setState(` search found only the processor's New assignment and common changeState helper, plus model setter declarations. There is no implemented cancellation endpoint or other application state writer. The schema accepts Cancelled; no cancellation feature was invented.
- React's account dropdown displays displayName, not the numeric account key (`web-front-end/react/src/AccountsDropdown/AccountsDropdown.tsx:15-19`). Its existing REST/feed inputs benefit from the server boundaries. React was inspected, not rendered or end-to-end tested.
- People-service has directory records, not client-account-number fields.
- Existing historical transitions already lost before migration cannot be reconstructed. Migration preserves real existing history and does not invent historical UTC timestamps. External/manual database writers are not verified.
